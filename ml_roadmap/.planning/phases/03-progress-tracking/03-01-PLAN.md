<task type="auto">
  <name>Task 1: Create progress.js and configure mkdocs.yml</name>
  <files>docs/javascripts/progress.js, mkdocs.yml</files>
  <action>
Create `docs/javascripts/progress.js` implementing checkbox persistence with these functions:

1. **isStorageAvailable()** -- write/read/delete test cycle, returns boolean
2. **getProgress()** -- reads localStorage key "progress", parses JSON, returns object. Wrapped in try/catch, returns {} on failure.
3. **saveProgress(progress)** -- JSON.stringify and write to localStorage key "progress". Wrapped in try/catch.
4. **getPageKey()** -- derives page key from `window.location.pathname`. Strip trailing `/` and `/index.html`. Extract the last two meaningful path segments (e.g., `core-ml/supervised-learning`). This handles both local `mkdocs serve` and GitHub Pages deployment.
5. **initCheckboxes()** -- queries all `.task-list-item input[type='checkbox']` on the page. If none found, return early. Restores checked state from localStorage (matching by index). Adds `task-checked` class to parent `.task-list-item` for checked items. Attaches `change` event listener to each checkbox that updates localStorage and toggles `task-checked` class. Also updates the stored `total` count to handle content edits gracefully (prune checked indices that exceed new total).

Wire everything via `document$.subscribe(function() { initCheckboxes(); })` -- this ensures re-initialization on every instant-loading navigation. Attach listeners directly to checkbox elements (not event delegation) so they are naturally garbage collected when DOM is replaced.

In **mkdocs.yml**:
- Add `clickable_checkbox: true` under `pymdownx.tasklist` (alongside existing `custom_checkbox: true`)
- Add `- javascripts/progress.js` to `extra_javascript` list (after the MathJax entries)

Use ES5-compatible syntax (var, function declarations, indexOf instead of includes) for broad browser support. Do NOT use arrow functions or const/let.
