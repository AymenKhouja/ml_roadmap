**Structure (4 sub-topics, ~3-4 hours total):**

1. **Why Read Papers** (~30 min): ML papers as the primary source of state-of-the-art knowledge — textbooks lag 2-5 years behind research frontiers. Reading papers lets you understand what tools actually do under the hood (e.g., understanding the Attention Is All You Need paper makes Transformers less magical). Career differentiation: engineers who read papers can implement new techniques from scratch, not just use existing APIs. Give concrete examples of papers every ML practitioner should know: "Attention Is All You Need" (Vaswani 2017), "BERT" (Devlin 2018), "Batch Normalization" (Ioffe 2015).

2. **The Three-Pass Method** (~1 hour): Keshav's canonical approach. First pass (5-10 min): title, abstract, introduction, section headings, conclusions — answers "is this relevant?" Second pass (30-60 min): figures, tables, key results, related work — answers "what do they claim?" Third pass (2-4 hrs): full line-by-line understanding — answers "could I reproduce this?" Emphasize that most papers only need the first or second pass. Name specific papers to practice each pass on. Teaching moment: the third pass is how you truly learn — not from tutorials, but from the authors themselves explaining their reasoning.

3. **Critical Evaluation** (~1 hour): Identifying key contributions (the 1-2 things the paper genuinely claims to advance). Evaluating experimental methodology: are the baselines appropriate? are the datasets standard? do ablation studies justify architectural choices? Common weaknesses: missing baselines, overfitting to one benchmark, cherry-picked qualitative examples, no statistical significance testing. OpenReview.net as a resource — reading peer reviews teaches you what experts look for. Teach the difference between "interesting result" and "reliable result."

4. **Building a Reading Workflow** (~30 min): Tools for organizing papers: Zotero (free, open-source), Mendeley (free), Paperpile (paid). Annotation strategies: highlight the problem statement, contribution, and key result; write a 3-sentence summary immediately after reading. Reading groups for accountability. Sustainable pace: 2-3 papers per week for practitioners is realistic and high-value. "Just-in-time" reading: read papers when you encounter the technique, not proactively. Give specific starting papers for practitioners new to reading research.

**Prerequisite admonition:** Complete Core ML section before this page — you need ML concepts to understand ML papers.
**Time/Difficulty:** ~3-4 hours | Intermediate
**Learning outcomes (5 bullets):** use the three-pass method, identify key contributions, evaluate experimental methodology, spot common weaknesses, build a sustainable workflow.

**Next up link:** `**Next up:** [Reproducing Results](reproducing-results.md) -- from reading papers to implementing them`

Replace the placeholder stub entirely. Write a full content page for RSCH-02 using the content plan from 08-RESEARCH.md (lines 203-213). Frame reproduction as the bridge between reading papers and doing research — the highest-leverage skill for deepening understanding.

**Structure (4 sub-topics, ~4-5 hours total):**

1. **Why Reproduce** (~30 min): Reproduction deepens understanding in a way reading never can — you encounter every ambiguity the authors glossed over. Tests your implementation skills against a known target. The ML reproducibility crisis: a 2019 study found fewer than 15% of ML papers could be reproduced exactly. Practical benefits: builds a portfolio of implementations, surfaces gaps in your own knowledge, sometimes discovers the paper's official results were run under special conditions not disclosed. The ML Reproducibility Challenge as motivation — external accountability and community.

2. **Reproduction Workflow** (~1.5 hours): Concrete step-by-step workflow: (1) Choose a well-known paper with an official implementation — start with papers from NeurIPS/ICML/ICLR with Papers With Code entries. (2) Read the paper thoroughly using the three-pass method. (3) Find official code on GitHub or Papers With Code. (4) Set up the exact environment specified (Python version, library versions, CUDA version if applicable). (5) Run the official code first and verify you match the reported numbers. (6) Then implement your own version from scratch using the paper only. (7) Compare your results to official results — differences are learning opportunities. Papers to start with: "Attention Is All You Need" for experienced practitioners, "A Neural Algorithm of Artistic Style" for beginners (simpler architecture). Papers With Code as the canonical starting point for finding implementations.

3. **Common Pitfalls and Debugging** (~1.5 hours): Missing implementation details: batch normalization parameters, learning rate scheduling, weight initialization, data augmentation not mentioned in the main paper (check appendix and author comments). Hyperparameter sensitivity: many papers report peak performance from extensive sweeps; your reproduction should start with the exact hyperparameters reported, not defaults. Library version differences: PyTorch 1.x vs 2.x, NumPy version differences, CUDA/cuDNN version effects on reproducibility. Numerical precision: float32 vs float16 differences, platform-specific random number generation. Dataset preprocessing differences: normalization statistics, augmentation order, train/val split strategy. Undocumented tricks: check GitHub issues and paper author responses for implementation clarifications that did not make the paper. Tip: when stuck, read the paper's appendix and the official code's training script — the training script is often more honest about implementation details than the paper.

4. **Contributing Back** (~30 min): When and how to contact authors — open a GitHub issue first, be specific about what you tried, share your reproduction code. Contributing to Papers With Code: add your reproduction as a "result" with a link to your repo. Writing a reproduction report: what you did, what you found, where results diverged. The ML Reproducibility Challenge (annual NeurIPS workshop): structured way to do a reproduction and get community credit. Hugging Face model hub as a platform for sharing implemented models from papers.

**Prerequisite admonition:** Complete Reading Papers page and Deep Learning Frameworks before this page — you need paper reading skills and a framework (PyTorch or TensorFlow) to implement architectures.
**Time/Difficulty:** ~4-5 hours | Advanced
**Learning outcomes (5 bullets):** set up a reproduction environment, follow the reproduction workflow, debug common failure modes, contact authors productively, contribute reproductions back to the community.

**Next up link:** `**Next up:** [Staying Current](staying-current.md) -- building a sustainable system for tracking ML developments`

Anti-patterns to avoid: Give specific paper names for practice. Concrete pitfall examples with specific tools (not "library issues" but "PyTorch 2.x changed default behavior for..."). Do not make pitfalls abstract.
